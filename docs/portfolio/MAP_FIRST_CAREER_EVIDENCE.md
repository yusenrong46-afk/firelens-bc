# Career evidence and interview language

Use only statements that match the released candidate's evidence. Keep implementation,
local testing and production deployment distinct.

## AI engineer résumé bullets

- Directed AI-assisted development of FireLens, combining official geospatial
  feeds with retrieval-grounded guidance, typed response contracts and inspectable
  source evidence for B.C. wildfire information.
- Designed a frozen 24-case context regression comparison; directed repairs that
  improved the measured offline result from 15/24 to 24/24, with nine paired wins
  and no losses while retaining the approved corpus and configured models.
- Integrated component and browser checks for conversation binding, exact-source
  support, immutable answer evidence, provider failure and responsive map workflows.

## AI implementation / solutions specialist résumé bullets

- Translated resident information needs into map, nearby-record, preparedness and
  source-inspection workflows with explicit authority, privacy and failure states.
- Coordinated a staged release process on an existing Vercel project using candidate
  identities, bounded preview/production smoke plans, operational documentation and
  rollback controls.
- Produced technical and user-facing handoff materials explaining setup, supported
  tasks, evaluation evidence and remaining limitations in plain language.

Do not change “staged release process” into a successful deployment claim until the
public verification receipt exists. No adoption, revenue, time-savings or enterprise
customer claims are supported.

## 60-second explanation

“I built FireLens to help B.C. residents inspect official wildfire records and find
source-backed preparedness information. I directed the requirements, constraints,
investigation and review, with OpenAI Codex assisting implementation and testing.
The key design choice is separating official data, reviewed guidance and general
background. A citation alone is not enough, so answers retain supporting passages,
limitations and source identities. I reproduced two conversation failures: a pet
follow-up lost the bag context, and a new fire lookup inherited weather context.
A frozen offline comparison improved from 15 of 24 cases to 24 of 24 after narrow
repairs. That is regression evidence, not a general accuracy claim. The work taught
me to test the user journey as well as the component, preserve failed evidence,
and tie release claims to the exact version that was tested.”

# FireLens V1.6 GitHub update standard

Status: binding for Codex and other coding agents on V1.6 work.
Date: 2026-08-23

This standard governs local commits, public prose (`README.md` and
equivalent), remote updates, pull requests, and merges.
It does not authorize deploy, paid H4, or firewall publish.

Public GitHub history must read as Thomas's engineering record, not as
an OpenAI / Codex product dump.

It aligns with:

- `CONTRIBUTING.md`
- `.github/pull_request_template.md`
- `docs/releases/V1_6_RUNBOOK.md`
- prior V1.5 / V1.6 loop discipline: local-only by default, focused
  commits, secret-scan before recovery artifacts, no force-push to
  protected branches

## Default posture

```text
commit locally when asked
push only when the human explicitly authorizes this session
open a PR only when the human explicitly authorizes this session
never merge to main
never deploy
```

Silence is not authorization.

A V1.6 engineering loop that says “do not push” overrides this document
for that loop.

## Authority

The human owner is the publication and release authority.

Codex / Cursor / other agents may:

- create local branches
- make focused commits when asked
- record exact commit / tree / hashes
- draft PR text

They may not:

- invent reviewer identity
- mark unreviewed typed claims approved
- treat a local pass as deployed or independent-exam evidence
- update `git config`
- change committer / author to OpenAI, Codex, ChatGPT, or a bot
- add `Co-authored-by` trailers for OpenAI, Codex, ChatGPT, Cursor, or
  any vendor agent
- skip hooks (`--no-verify`, `--no-gpg-sign`) unless the human
  explicitly requests it
- rewrite history on a branch that has already been pushed

## Branch naming

Use one working branch per loop. Do not commit on `main`.

| Kind | Pattern | Example |
| --- | --- | --- |
| Architecture / upgrade | `upgrade/v1-6-<topic>` | `upgrade/v1-6-structured-publication-harden-1` |
| Human claim review | `review/v1-6-typed-claims-batch-N` | `review/v1-6-typed-claims-batch-1` |
| Examined rollback | `examined/v1-6-<name>` | `examined/v1-6-structured-publication` |
| Recovery | `recovery/v1-6-<reason>-<date>` | `recovery/v1-6-pre-clean-20260823` |

Do not use `codex/v1-6-moat-tutorial`.
Do not reuse a frozen examined branch as a working branch.

## Commit standard

Create commits only when the human asks, or when a written loop
explicitly requires focused commits.

### Before every commit

Run in parallel:

```text
git status
git diff
git log -8 --oneline
```

Then:

1. Confirm the active branch is the intended working branch.
2. Confirm no secrets, `.env`, credentials, or paid/sealed reports
   are staged.
3. Run `make secret-scan` or `.venv/bin/python scripts/secret_scan.py`
   before recovery artifacts, snapshots, or any first push.
4. Stage only files that belong to this commit family.

### Commit shape

One concern per commit. Prefer the V1.6 families:

```text
1. current-flow / ADR / state
2. failing tests
3. contracts
4. compiler / routing
5. fallback / inventory / review queue
6. frontend contract
7. evaluation evidence
8. freeze
```

Do not combine unrelated work.
Do not amend unless all of these are true:

- the human explicitly asked to amend, or a hook rewrote files in a
  commit this agent just created
- HEAD was created by this agent in this session
- the commit has not been pushed

If a hook rejects a commit, fix the issue and create a **new** commit.
Do not `--amend` a rejected commit.

### Message form

Use a HEREDOC. Two sentences. Lead with why.

```text
git commit -m "$(cat <<'EOF'
Harden claim-to-span binding so uncovered high-risk text stays quote-only.

The compiler remains the only STRUCTURED_REVIEWED constructor.
EOF
)"
```

Allowed verbs: `add`, `update`, `fix`, `harden`, `record`, `freeze`.
Do not claim “pass,” “qualified,” or “ready for paid H4” in a commit
message unless the corresponding evidence file already exists.

Do not append any of:

```text
Co-authored-by: Cursor <...>
Co-authored-by: Codex <...>
Co-authored-by: OpenAI <...>
Co-authored-by: chatgpt <...>
Made-with: Codex
Generated by ChatGPT
Signed-off-by: OpenAI
```

Author and committer stay the local human identity already configured
(`Thomas <yusenrong46@gmail.com>`). Do not change `user.name` or
`user.email`.

## README and public prose

`README.md` is the public face of the repo. Write it as Thomas would:
an engineer explaining a safety-critical product, not a model announcing
a launch.

The voice to copy is the current `README.md`:

- short complete sentences
- one organizing idea, then consequences
- exact about evidence, status, and what is still open
- no hype

### Required README shape

When you must edit `README.md`:

1. Read the current file first. Preserve its structure unless the human
   asked for a rewrite.
2. Keep the product definition, authority sentence, and honesty about
   unproven gates.
3. Update only the stale facts (version, branch, live URL, command
   table, remaining blockers).
4. Link ledgers and ADRs instead of restating a campaign recap.
5. Keep the authority line in this family:

```text
A language model chooses tools and writes prose. It is never the
authority for what is true.
```

or the shorter form already used:

```text
Models propose language. Source contracts, deterministic validation,
and humans decide.
```

### Voice rules

Write like this:

```text
FireLens BC is an answer-first wildfire assistant for British Columbia, with map context when it is relevant.
Conversational AI fails worst exactly where it sounds best.
Cached-stale records are never called "current".
```

Do not write like this:

```text
We're excited to introduce FireLens, a next-generation AI-powered
wildfire copilot built with GPT-5.6 / Codex!

✨ What's new
🚀 Powered by OpenAI
Leverage cutting-edge multimodal agents to delight users.
```

Forbidden in `README.md`, PR bodies meant for merge, and merge commits:

- first-person vendor voice (`we at OpenAI`, `Codex implemented`,
  `ChatGPT generated this`)
- emojis, badge walls, “What's New” changelogs, star-begging
- `leverage`, `delight`, `seamless`, `robust solution`, `game-changer`,
  `cutting-edge`, `AI-powered` as decoration
- claiming human review, paid H4, or release GO without a cited ledger
- naming OpenAI, Codex, ChatGPT, or Cursor as authors of the product
  or the commit
- OpenRouter / model IDs are allowed only as runtime configuration,
  the same way the current README already lists them

If a README change would make the file look generated, do not make it.
Leave a short note for the human instead.

### Status honesty

README release status must stay conservative. Prefer:

```text
engineering candidate
automated verification
named human review remains open
```

over:

```text
production-ready
fully qualified
OpenAI-verified
```

## Merge standard

Default remains: **do not merge** unless the human explicitly says
`merge this PR` or `squash-merge to <branch>`.

When a merge is authorized, the GitHub history must still look like
Thomas merged engineering work. It must not look like an OpenAI bot
landed a branch.

### Preferred merge method

```text
squash and merge
```

Use the human-authored squash title and body. Do not keep GitHub's
default `Merge pull request #N from openai/...` or
`Merge branch 'codex/...'` subject.

Local equivalent if `gh` merge branding cannot be stripped:

```text
git checkout <target>
git merge --ff-only <feature>     # only if fast-forward is possible
# otherwise squash locally:
git merge --squash <feature>
git commit -m "$(cat <<'EOF'
Harden structured publication binding for uncovered high-risk spans.

Unreviewed records stay pending. Quote-only remains the fallback.
EOF
)"
git push origin HEAD
```

Do not use GitHub's “merge commit” if it will record:

```text
Merge pull request #12 from openai/codex/v1-6-...
Merge pull request #12 from cursor/agent-...
```

Rename remote feature branches away from `openai/`, `codex/`, and
`cursor/` prefixes before a public merge if the human wants the
history clean. Preferred public names stay in the table above
(`upgrade/...`, `review/...`).

### Attribution rules at merge

1. Author = `Thomas <yusenrong46@gmail.com>`.
2. No vendor `Co-authored-by` trailers.
3. No `Made-with`, `Generated-by`, or `Signed-off-by: OpenAI`.
4. PR title and squash message use product language, not
   `Codex:`, `GPT:`, or `Agent PR`.
5. Do not enable GitHub merge-queue comments that paste model
   transcripts into `main`.
6. Do not add an “Assisted by Codex / OpenAI” section to README,
   the PR, or the merge commit.
7. If `gh pr merge` would attach bot authorship, stop and merge
   locally so the commit is Thomas's.

Authorized merge command family:

```text
gh pr merge <n> --squash --delete-branch --subject "<why>" --body "$(cat <<'EOF'
<two human sentences, no vendor credit>
EOF
)"
```

or local squash as above.

After merge, report:

```text
MERGED
method: squash-local | squash-gh | ff-only
author: Thomas <yusenrong46@gmail.com>
vendor trailers: none
commit:
tree:
PR URL:
```

If vendor trailers cannot be removed, **do not merge**. Return
`BLOCKED_VENDOR_ATTRIBUTION` and ask the human.

## Push authorization

Push only when the human writes one of:

```text
push this branch
push to origin
open a pull request
update the GitHub branch
```

If authorization is missing, stop after local commits and report:

```text
LOCAL_ONLY_NOT_PUSHED
```

### First push of a branch

```text
git status --porcelain
git rev-parse --abbrev-ref HEAD
git rev-parse HEAD
git rev-parse 'HEAD^{tree}'
make secret-scan
git push -u origin HEAD
```

Use `gh` for GitHub inspection and PR creation. Do not use the GitHub
web UI as the primary method.

### Later updates of the same branch

```text
git status --porcelain
git push origin HEAD
```

Expected result: fast-forward or ordinary new commits on the same
remote branch. Record the new HEAD and tree.

### Workflow-file exception

If the push includes `.github/workflows/*` and GitHub rejects it
because the token lacks `workflow` scope, **stop**. Do not force-push.
Do not strip workflow files to sneak the branch up.

Owner action only:

```text
gh auth refresh -h github.com -s workflow
git push -u origin HEAD
```

This failed on `codex/v1-5-v3` historically. Same rule now.

## Forbidden git operations

Never, unless the human names the exact command in this session:

```text
git push --force
git push --force-with-lease to main or master
git reset --hard
git rebase -i
git add -i
git commit --amend   (except the narrow amend rule above)
git config ...
```

Never force-push `main` or `master`. Warn and refuse.

Never push:

- `.env` or credentials
- sealed H4 labels
- paid qualification reports under `output/qualification/`
- examiner held-out catalogs
- secrets discovered by `secret-scan`

## Pull request standard

Open a PR only after an authorized push of the exact candidate.

Required preflight:

```text
git status --porcelain          # must be empty
git rev-parse --abbrev-ref HEAD
git rev-parse HEAD
git rev-parse 'HEAD^{tree}'
git log --oneline <base>...HEAD
git diff <base>...HEAD
```

Use `gh pr create`. Body must follow `.github/pull_request_template.md`
plus a V1.6 identity block.

```text
gh pr create --title "<why, not ticket slang>" --body "$(cat <<'EOF'
## Intended behavior

- [x] Acceptance criteria were frozen before implementation.
- [x] Every new interface exists in the repository or version-matched primary documentation.

## Identity

- Branch:
- Commit:
- Tree:
- Package: 1.6.0rc1 / 1.6.0-rc.1
- Base branch:

## Evidence

- Inspected:
- Executed:
- Not run:
- Hard probe:
- ClaimBench:
- `make verify`:

## Safety and privacy

- [x] No benchmark label or threshold was changed to fit the implementation.
- [x] No query, answer, deterministic query hash, precise location, secret, or human-review content was added to telemetry.
- [x] Provider fallback remains disabled. Embedding and generation ZDR remain fail-closed.
- [x] No typed claim was marked human-reviewed by the coding agent.

## Review

- [x] Generated OpenAPI and frontend types are synchronized, or unchanged.
- [x] Targeted tests pass.
- [x] `make verify` passes, or missing evidence is stated explicitly.
- [ ] Critical changes have named human review.

## Test plan

- [ ] Architecture tests
- [ ] Typed-inventory tests
- [ ] Offline hard probe >= 86/105, zero paired regression
- [ ] Frontend vitest / e2e if UI contract changed
- [ ] Confirm no secrets in the diff

## Out of scope

- Paid H4
- Merge to main
- Preview / production deploy
EOF
)"
```

Do not target `main` for merge-ready release PRs unless the human
explicitly asks for a draft inspection PR. Prefer draft PRs for
independent examination:

```text
gh pr create --draft ...
```

Return the PR URL. Do not merge. Do not enable auto-merge.

Do not continue into deploy, paid H4, or another unrelated loop.

## Alignment with evidence vocabulary

Label GitHub conclusions:

```text
EXECUTED    command was run in this session
INSPECTED   read from git / gh / files
INFERRED    reasoned, not proven
BLOCKED     auth, scope, or policy stopped the update
EXTERNAL    GitHub / CI result not locally re-run
```

A green local `make verify` is not GitHub CI proof.
A pushed branch is not a release.

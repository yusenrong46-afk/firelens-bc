# Appendix — Glossary

**AgentQueryPlan** — Frozen application-owned authorization for one request: route, mode, layers, geography, subrequest, and exact calls.

**AnswerSection** — User-visible response part with an application-owned authority label such as current records or reviewed guidance.

**Available zero** — A successfully observed live layer with no matching strict records. It is not an all-clear.

**Candidate** — A clean, exact commit/tree plus bound artifacts proposed for qualification. The current branch `HEAD` is a local candidate, not a deployed or release-qualified one.

**ClaimBench** — Deterministic faithful/mutated claim corpus used to test publication validators; not a semantic-completeness proof.

**Coarse location** — Community label or coordinate pair rounded to two decimals for the current live request.

**Current** — Verified against the active named base or candidate identity; never shorthand for “mentioned in a recent file.”

**Deterministic derivation** — Application calculation, such as geodesic distance, with bound inputs, algorithm, CRS, units, time, and validation state.

**EvidencePacket** — Bounded, versioned set of admitted spans, quote candidates, conflicts, and limitations for one static question.

**First divergence** — Earliest stage whose structured output differs from the product contract; the preferred repair owner.

**Fresh** — Source observation within the implemented freshness/clock policy. It does not guarantee source correctness.

**General background** — Model explanation explicitly not represented as reviewed-corpus or current official evidence.

**Grounded** — Response mode whose reviewed claims carry exact support and publication authority.

**Historical** — Evidence bound to a different commit, tree, dataset, evaluator, deployment, or product state.

**Layer** — One supported official live record family: incident, perimeter, or fire-related evacuation.

**LiveResult** — Strict normalized official record with source, observation/retrieval time, freshness, geometry, and optional derived distance.

**Mixed** — Response with visibly separated evidence lanes, usually official current records plus reviewed guidance or labelled background.

**Official quote-only** — Exact admitted official source wording labelled extraction-only; not a human-reviewed structured claim.

**Partial** — Useful supported content plus an explicit unresolved/unavailable part; not complete coverage.

**ProductBench** — Product-behavior cases and predicates; its offline tier uses a deterministic fake provider.

**Proof card** — Backend-derived projection of one claim’s support, authority, review, freshness, truth class, and publication state.

**PublicationAuthority** — Machine-readable binding that determines how a claim may be represented publicly.

**Requires input** — Resumable response asking for bounded missing location, source, or clarification.

**Reviewed guidance** — Stable admitted-corpus material; high-risk public claims additionally require typed review authority or exact quote-only treatment.

**Roster** — Ordered authorized live result set used for list/map selection and ordinal follow-ups.

**Sealed holdout** — Evaluation set whose labels and access are controlled so tuning cannot consume the qualification evidence.

**Selected record** — Exact live result ID supplied in bounded request context for a follow-up.

**Stale** — Cached official observation after refresh failure; explicitly not current conditions.

**Terminal response** — Application-owned response that completes the request before tool/evidence execution.

**Unavailable** — FireLens could not establish a layer or capability. It must not be rendered as zero or empty.

**ZDR** — Zero-data-retention routing requirement at a named provider stage; it is stage- and model-specific, not a universal privacy claim.

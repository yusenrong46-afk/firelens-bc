## 2. Intended Use

- Explore typed official BC wildfire incident, perimeter, and fire-related evacuation records.
- Find records near a voluntarily supplied coarse location.
- Read stable reviewed preparedness guidance with inspectable source support.
- Ask bounded follow-ups about prior sources, places, or selected live records.
- Receive clearly labelled general background for adjacent ordinary questions.

## 3. Out-of-Scope Uses

Emergency warning; deciding whether someone is safe, should stay, return, or evacuate; evacuation route selection; medical advice; property-specific risk; prediction; comprehensive incident enumeration; exact-address processing; open-web research; and autonomous operational decision-making.

## 4. Composition

The React/Vite browser client calls a FastAPI service. The API builds a deterministic `AgentQueryPlan`, executes only exact authorized official-live and/or static-RAG tools, optionally obtains bounded model output, compiles or validates public claims, composes authority-labelled sections, and validates the final `AskResponse`. See the [Architecture Book](../architecture/README.md) and [request lifecycle](../architecture/04-request-lifecycle.md).

## 7. Authority Model

AI may interpret broadly and draft/explain within a bounded packet. Deterministic software owns tools, live layers, geography, selected record, official values, retrieval packet identity, publication kind, supported high-risk text, derivations, proof state, and final response validation. Authorized humans own source admission, typed high-risk review, sealed evaluation decisions, and release approval.

Models cannot grant themselves capability or publish official/reviewed truth. See [Safety and authority](../architecture/09-safety-and-authority.md).

## 8. Evaluation Methodology

Evaluation freezes application, dataset, evaluator, provider/judge, and environment identity; finds the first divergence; adds a regression and neighboring cases; repairs the earliest owner; then proceeds from deterministic tests to authorized external and human gates. Dirty application identity is a 64-character digest over the base revision, binary tracked diff, and untracked paths/bytes; source is captured before and after a run. Dirty/source-changing evidence cannot pass. Comparison validates each eligible envelope against a detached snapshot of its own commit, replays all four core adapters, and refuses incompatible evaluator, policy, schema, or dataset bindings. Unverifiable ProductBench random-trace response hashes are omitted and rejected if reintroduced. Development data is not a sealed holdout. Model judges require human calibration and explicit prompt/model binding.

Current catalog identities and roles are in the [Evaluation Catalog](../architecture/appendices/evaluation-catalog.md).

## 11. Prompt Injection

Input rails can terminate policy-manipulation requests before evidence work. More importantly, every later tool name and normalized argument map must match the frozen application plan, and repeated dispatch is rejected. Output publication is independently validated. Current offline injection tests do not prove resilience against all adaptive attacks or deployed integrations.

## 12. Hallucination and Evidence Behavior

Official live text is rendered from typed records. Reviewed Tier A/B facts compile from human-reviewed typed claims or exact admitted official wording; unsupported high-risk content becomes partial, unknown, handoff, or abstention. Background cannot cite the reviewed corpus.

Remaining risk: lower-risk generated claims use bounded lexical/deterministic validation; exact quote occurrence does not prove full semantic entailment, retrieval can miss material, and source data itself may be wrong.

## 13. Fault Handling

Typed public errors distinguish invalid request, rate/body limits, not-ready, provider, deadline, live source, and selected-record failures. Live availability is per layer. The local candidate repair quarantines an entire layer when any otherwise-in-scope official row has invalid/unclassifiable geometry or cannot satisfy `LiveResult`; healthy sibling layers remain, while successful empty remains available-zero.

Unexpected programming failures are sanitized publicly and loud in local/test paths. Some early failure branches have incomplete normal request telemetry.

## 14. Privacy

The API accepts bounded question/history and optional coarse location. Exact-address-like labels are rejected; coordinates are rounded to two decimals. Operational/feedback/product events do not accept raw question, answer, history, coordinates, evidence text, or secrets. Default traces are content-minimized.

Explicit local content tracing may retain raw question text. Preview/production configuration rejects it. OpenRouter privacy/ZDR configuration is stage-specific and is not a privacy certification or observed deployment attestation.

# FireLens fix

## Trigger

Use only after `firelens-examine` has produced a confirmed FailureRecord with a
supported first divergence and owner.

## Purpose and input

Input is that FailureRecord and the protected-neighbor impact slice. Produce the
smallest generalized correction plus executable regression evidence.

## Allowed actions

- Edit the confirmed owner and focused tests/evaluation data.
- Run original, mutation-family, neighboring-capability, and invariant tests.
- Remove a superseded workaround only when current evaluation protects it.

## Forbidden actions

- Do not patch final prose when an earlier structured layer is wrong.
- Do not add phrase-specific branches when a typed semantic contract fits.
- Do not widen model/tool/source authority or weaken an existing safety floor.
- Do not change frozen expectations to manufacture a pass.

## Workflow

1. Reproduce the failure before editing.
2. Confirm owner and impact with `firelens-map`.
3. Add the failing original case and at least one semantic neighbor.
4. Implement the smallest owner-level contract correction.
5. Re-run original, mutations, neighbors, and protected invariants.
6. Update the FailureRecord to `fixed` only with exact candidate evidence.

## Output schema

`failure_record`, `first_divergence`, `changed_owner`, `general_contract`,
`regressions`, `protected_results`, `remaining_risk`, `candidate_identity`.

## Stop and handoff

Stop if the record cannot be reproduced or the owner is ambiguous. Hand stable
subsystems with evidenced duplication to `firelens-simplify`; otherwise evaluate.
